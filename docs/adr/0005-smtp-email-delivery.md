# ADR-0005: Email через SMTP (MailHog у dev, AWS SES у prod)

- **Статус:** Прийнято
- **Дата:** 2025-04-12
- **Дотичні ADR:** [0001](0001-hexagonal-architecture.md), [0007](0007-token-based-confirmation.md)

## Контекст

Сервіс зобов’язаний:

- надсилати **лист підтвердження** при підписці;
- надсилати **повідомлення про новий реліз** усім підписникам відповідного репо;
- бути **простим у локальній розробці** (бачити лист, не маючи реальної пошти);
- працювати в проді з прийнятною доставлюваністю та DKIM/SPF.

## Розглянуті варіанти

1. **Прямий SMTP** через стандартний `net/smtp` + контейнер MailHog у dev і керований SMTP‑провайдер (AWS SES) у prod.
2. **HTTP API провайдера** (SES API, SendGrid, Mailgun): зручне DKIM, ретраї на боці провайдера, але vendor‑lock на ранній стадії.
3. **Власний MTA** (Postfix/Exim): надмірне з точки зору цілей курсу, потребує доглядати reputation/IP.

## Рішення

Обрано **варіант 1**: SMTP‑адаптер `internal/adapter/outbound/email/sender.go`:

- залежності: `host/port/user/password/from/timeout`;
- з’єднання через `net.Dialer`, дедлайни з контексту або `SMTP_TIMEOUT`;
- умовний `STARTTLS` (якщо сервер його повідомляє в `EHLO`);
- `PLAIN AUTH` лише коли вказано `user/password`.

У dev (`docker-compose.yml`) піднято **MailHog**:

- `SMTP_HOST=mailhog`, `SMTP_PORT=1025`;
- `SMTP_USER=""`, `SMTP_PASSWORD=""` — інакше Go відмовляється робити PLAIN AUTH по нешифрованому каналу;
- UI на `http://localhost:8025`.

У prod очікується SES (порт 587, STARTTLS, реальні `SMTP_USER/PASSWORD`).

Поверх відправки в `NotifierService` і місцях підтвердження — **експоненційний backoff** із класифікацією помилок (`isTransientMailError` за рядком: `dial`, `timeout`, `EOF`, `reset`, …).

## Наслідки

**Плюси**

- Один код для dev і prod, відрізняються тільки ENV.
- MailHog усуває потребу в реальній пошті при локальній розробці й тестах підтвердження.
- Стандартний SMTP — вільний вибір провайдера в проді (SES, Mailgun, інший).

**Мінуси / трейдофи**

- `net/smtp` примусово блокує `PLAIN AUTH` без шифрування — потрібно тримати MailHog з порожнім логіном/паролем (це й документовано в `.env.example`/compose).
- Класифікація transient‑помилок за substring рядка — крихка; у майбутньому варто «занести» провайдерські коди (4xx vs 5xx SMTP) як окремі типи помилок.
- Власний throttling/quota на стороні застосунку поки не реалізовано — покладаємось на SMTP‑провайдера.

## Майбутнє

- Винести розсилку в окрему чергу повідомлень → асинхронні воркери з retry і dead‑letter.
- Поступово замінити `net/smtp` на бібліотеку з повноцінним SMTP‑state machine (наприклад, `go-mail`) для кращого контролю помилок.
